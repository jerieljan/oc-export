# Compact-Thinking Methodology for Opencode Chat HTML Exports

This document describes how to collapse the verbose thinking and tool-call blocks inside an Opencode chat session HTML export into compact summaries, producing a much shorter, still-readable file.

## Source format

Each assistant turn may contain two kinds of collapsibles, generated by `src/render.ts` in this repo:

- `<details class="collapsible thinking">` ... one or more `<div class="thinking-block">` ... `</details>`
- `<details class="collapsible tools">` ... many nested `<details class="collapsible tool">` ... `</details>`

User turns do not contain collapsibles. The page structure is `<main class="container chat">` with `<article class="turn ...">` children; preserve these.

The page is a single self-contained HTML file with inline `<style>` and a `<script>` for the theme toggle. Do not change anything outside the collapsibles.

## Output rules

1. Each `<details class="collapsible thinking">` becomes one summary `<details>` with:
   - `<summary>Thinking summary</summary>` (or, optionally, the original turn's mode, e.g. "Thinking summary (plan)")
   - A single `<div class="thinking-block">` containing 1-3 paragraphs that cover the assistant's reasoning, the open questions it raised, and the decisions it recorded.

2. Each `<details class="collapsible tools">` becomes one summary `<details>` with:
   - `<summary>Tool calls summary (N calls)</summary>` where N is the original count from the inner `Tool calls (N)` summary line
   - A single `<div class="thinking-block">` containing one short paragraph plus a `<ul>` of accomplishments (one `<li>` per meaningful action or group of related actions).

3. The original nested `<details class="collapsible tool">` blocks are discarded entirely. Their inputs and outputs do not need to be preserved.

4. Preserve everything else verbatim: the page header, the inline `<style>`, every `<article class="turn ...">` wrapper, the user messages, the assistant final messages, and the bottom `<script>` for the theme toggle.

## Summarization approach

For each turn, before writing the replacement, read the full block content and extract:

- Thinking blocks: the main question the assistant was reasoning about, the options it weighed, the decisions it committed to, and the clarifying questions it handed back to the user. Compress to 1-3 paragraphs. Keep concrete references to file paths, function names, flags, and behaviors so the summary is still useful when skimming the file later.
- Tool blocks: scan the sequence of `<span class="tool-name">` entries plus the high-level intent visible in the inputs. Group consecutive `todowrite` updates into the surrounding step. Phrase each bullet as a completed action ("Wrote ...", "Verified ...", "Deleted ..."), not a raw tool name.

If a thinking block is very long (dozens of `<div class="thinking-block">` blocks, e.g. a build-mode turn), one paragraph should describe the plan, one should describe the design decisions made during the work, and one should describe what was tested or verified.

## Replacement procedure

The blocks are large and the file is large, so a line-based Python script is the most reliable approach. The procedure used in this repo:

1. Back up the file first.
2. Use `grep` to locate every `<details class="collapsible ...>` line; record the 1-based line numbers of each opening tag and the `class` value (`thinking` or `tools`).
3. For each opening tag, find the matching `</details>` by walking forward line by line and incrementing on `<details` and decrementing on `</details>`. The line where the depth returns to zero is the closing tag (1-based, inclusive).
4. Build a list of `(start_line, end_line, replacement_text)` for every block. For the `tools` blocks, also read the inner `Tool calls (N)` summary to capture N.
5. Apply replacements in reverse line order so earlier indices stay valid.
6. Write the file back and verify by parsing with BeautifulSoup: confirm the number of `<article class="turn ...">` elements is unchanged and that only the expected summary collapsibles remain (one per original block).

Reference script: `/tmp/summarize.py` from the session that produced this file. The relevant helpers are `find_matching_details_end` (depth-counted closing-tag search) and `replace_block` (1-based inclusive slice replacement).

## Verification checklist

After rewriting, confirm:

- File parses cleanly with BeautifulSoup (no mismatched tags).
- Number of `<article class="turn ...">` elements equals the original turn count.
- Number of `<details class="collapsible ...">` elements equals the number of original blocks (each `thinking` and each `tools` becomes exactly one summary block, not zero, not many).
- The page header, inline `<style>`, and bottom `<script>` are still present and unchanged.
- The new line count is a small fraction of the original (typically 4-5x reduction).

## When not to apply

Skip this compaction if the user explicitly wants the raw tool output preserved for debugging, if they want to diff against an uncompacted version, or if the session is being used as a reference example that needs to show the full tool inputs and outputs.
